## 1. Что выяснили (октябрь 2026)

| Вопрос | Ответ | Решение в QB |
|---|---|---|
| Есть ли открытый API реестра компаний по ИНН (ՀՎՀՀ)? | Нет. Госреестр (e-register.moj.am) и поиск налогоплательщиков КГД — веб-формы. Есть платные посредники (Apify-актор над открытыми данными реестра, karg.am) — точность и условия не проверены | Порт `integrations/registry.py`: сейчас `demo` (вымышленные компании) и ручной ввод. Платный источник подключается новым адаптером без изменения сервисов |
| Есть ли публичный API КГД для e-счетов и путевых листов? | Не подтверждён. Известно: e-счета обязательны для плательщиков НДС, с 1.03.2025 у строк без 20% НДС есть поле «тип операции», по HO-309-N (с 1.09.2026) счёт — до поставки, путевой лист — до начала перевозки | QB печатает свои документы; официальный e-счёт и e-путевой лист продавец выписывает в системе КГД и вносит их номера в заказ |
| Какие документы проверять у поставщиков еды? | Учёт в Инспекции пищевой безопасности, сертификат/декларация ЕАЭС, ветеринарно-санитарное (животное происхождение), фитосанитарное (растительное), HACCP (обязателен для части производителей), лицензия на алкоголь | Слоты загрузки: обязательна выписка из госреестра, остальное — желательно, решает оператор |

Источники: [Apify — Armenia Company Registry](https://apify.com/reestri/am-company-lookup), [karg.am](https://karg.am/?lang=en),
[VATupdate — тип операции в e-счетах](https://www.vatupdate.com/2025/02/08/armenias-state-revenue-committee-introduces-new-transaction-type-field-for-e-invoicing/),

## 2. Регистрация компании

```mermaid
sequenceDiagram
  actor U as Пользователь
  participant Web as PWA
  participant API
  participant R as Реестр (порт)
  U->>Web: роль (покупаю / продаю) + ИНН
  Web->>API: GET /registry/lookup?tin=
  API->>R: lookup(tin)
  R-->>API: название, адрес, директор, режим налога (или ничего)
  API-->>Web: данные + «уже в QB?» + источник (demo / ...)
  U->>Web: проверяет и дополняет (банк, адрес доставки)
  Web->>API: POST /organizations
  API-->>Web: покупатель — active; продавец — pending
```

- ИНН — 8 цифр, пробелы и дефисы убираются. Один ИНН — одна компания в QB (`tin_taken`; вступление в существующую компанию — по приглашению, ещё не сделано).
- Закрытая по реестру компания не регистрируется (`company_inactive`).
- `registry_source`: `demo`/провайдер, если название совпало с реестром, иначе `manual` — оператор видит пометку «введено вручную».
- Вход для теста — `POST /auth/dev-register` (только при `DEV_LOGIN=true`). Настоящий вход — Telegram/почта, ещё не сделан.

## 3. Верификация

| Вид файла (`FileKind`) | Покупатель | Продавец |
|---|---|---|
| `state_registration` — выписка из госреестра | обязательно | обязательно |
| `food_safety_registration`, `conformity`, `veterinary`, `phytosanitary`, `haccp`, `alcohol_license` | — | желательно |

1. Компания загружает PDF/фото (до 10 МБ, только `pdf/jpeg/png/webp/heic`; имена файлов на диске случайные).
2. «Отправить на проверку» → `verification_status = pending` (нужен хотя бы один не отклонённый файл каждого обязательного вида).
3. Оператор (`is_platform_admin`) в «Модерации» одобряет/отклоняет файлы, затем компанию. Одобрить компанию можно, только когда обязательные файлы одобрены.
4. Одобрение: `verified`; продавец `pending → active` и начинает продавать. Все решения пишутся в `audit_log`.
5. Файлы видят только участники компании и операторы (`GET /files/{id}`); одобренный файл удалить нельзя.

## 4. Документы заказа

| Документ | Когда | Номер | Содержимое |
|---|---|---|---|
| Счёт на оплату (Հաշիվ վճարման համար) | подтверждение заказа | `INV-2026-0001` | реквизиты сторон с банком, строки, НДС, итог |
| Товарная накладная (Ապրանքագիր) | подтверждение заказа | `DN-2026-0001` | + раздел перевозки: откуда, куда, ТС и водитель (вписываются от руки), подписи «Сдал/Принял», М.П. |
| Акт приёма-передачи (Ընդունման-հանձնման ակտ) | приёмка | `ACT-2026-0001` | отгружено и фактически принято по строкам (недостача подсвечена) |
| e-счёт КГД, e-путевой лист | выписывает продавец в КГД | номер КГД | QB хранит только номер (`tax_invoice`, `waybill`) |

- Нумерация сплошная по продавцу, виду и году (`document_counters`, строка блокируется на время выпуска).
- `payload` «замораживает» реквизиты, строки и суммы на момент выпуска.
- НДС: цены включают НДС; НДС = сумма × 20/120 по строкам (ставка — снимок `order_lines.vat_rate_bp` при оформлении), скидка на заказ распределяется пропорционально, доставка — по ставке продавца. У неплательщика НДС — пометка «Поставщик не является плательщиком НДС».
- Печать: `/print/:id` — A4, армянский основной язык, язык пользователя мелко под ним; «Печать / PDF» через браузер. В подвале: «не является электронным документом КГД».
- Для заказов, подтверждённых до появления документов: `POST /orders/{id}/documents` выпускает недостающие (идемпотентно).

## 5. Что дальше

1. Подключить реальный источник реестра (сравнить Apify-актор и karg.am по точности, цене и условиям).
2. Интеграция с e-invoicing КГД (если появится API или через учётные программы) — тогда счёт и путевой лист выписываются из QB автоматически и до отгрузки.
3. Сроки действия сертификатов (`expires_on`) — напоминания и снятие значка «проверено» по истечении.
4. Значки в каталоге: «Проверенный поставщик», «HACCP».
5. Сумма прописью в счёте, поле «тип операции» КГД для строк без НДС.
