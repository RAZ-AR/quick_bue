# QB — закупки для HoReCa в Армении

Маркетплейс: оптовики, магазины и производители продают продукты и расходники, кафе и рестораны покупают.
Одна корзина на нескольких продавцов, торг (предложить цену, автопилот продавца), позже — счета и путевые листы
в системе КГД. Продукт и рынок — [docs/01-research-and-concept.md](docs/01-research-and-concept.md),
экраны, торг, модель данных и план — [docs/02-mvp.md](docs/02-mvp.md),
принципы, флоу, модули и правила слоёв — [docs/03-architecture.md](docs/03-architecture.md),
документы по законодательству РА, регистрация по ИНН и верификация — [docs/04-documents-and-verification.md](docs/04-documents-and-verification.md),
вход, гостевой режим, кабинеты и две роли — [docs/05-cabinets-and-auth.md](docs/05-cabinets-and-auth.md),
роадмап до Нового года — [docs/07-roadmap.md](docs/07-roadmap.md).

Языки интерфейса и каталога: армянский (`hy`), русский (`ru`), английский (`en`). Валюта — AMD, целые драмы.
Пользователю всё пишем по-русски; код, комментарии и коммиты — по-английски.

## Команды

```bash
cp .env.example .env
docker compose up -d --build                     # всё; api сам применяет миграции
docker compose run --rm api python -m app.seed   # демо-данные (вход: DEV_LOGIN, *@qb.local)
docker compose run --rm api python -m app.demo   # демо-данные + 6 заказов в разных состояниях

# тесты и линтер бэкенда (база qb_test в том же контейнере db)
docker compose run --rm -v "$PWD/backend:/app" -e TEST_DATABASE_URL=postgresql+asyncpg://qb:qb@db:5432/qb_test api pytest -q
docker compose run --rm -v "$PWD/backend:/app" api sh -c "ruff check . && ruff format --check ."

# новая миграция после правки моделей
docker compose run --rm -v "$PWD/backend:/app" api alembic revision --autogenerate -m "..."
docker compose run --rm -v "$PWD/backend:/app" api alembic check

# фронтенд
cd web && npm install && npm run dev   # http://localhost:5180, проксирует /api на :8010
npm test && npm run lint && npx tsc -b
```

```
│                  # mailer (console | resend) для кодов входа

├── auth/          # JWT, вход по коду на почту / Google / Telegram, current_actor (заголовки X-Org-Id, X-Mode)
├── core/          # search (search_text + транслит hy/ru → latin)
├── workers/       # outbox-диспетчер (пока только лог), очередь RQ "qb"
├── bot/           # Telegram-бот: /start и привязка чата к пользователю для уведомлений

└── demo.py        # seed + заказы через API: торг, в пути, оплачен; на сервере — вместо seed
```

## Правила

- **Деньги** — `bigint` в целых драмах (`Amd`), количество — `numeric(12,3)` (`Qty`). Ставки — в базисных пунктах (100 bp = 1%).
- **Enum** хранятся как VARCHAR + CHECK (`str_enum`). Автогенерация Alembic дублирует эти CHECK — после
  `--autogenerate` удаляйте строки `sa.CheckConstraint("<col> IN (...)")`, колонка `sa.Enum(..., create_constraint=True)`
  создаёт ограничение сама.
- Автогенерация не видит расширения и отдельные последовательности: `pg_trgm` и `order_number_seq` созданы вручную в `0001`.
- В строках заказа цена и название — **снимки** на момент заказа; комиссия и источник клиента копируются в заказ при приёмке.
- Цена для покупателя — `domain/pricing.resolve_unit_price`: договорённая в торге окончательна, иначе самая низкая из
  каталожной, объёмного порога и контрактной. В строке заказа `list_price_amd` — цена **до** торга; отклонённое
  предложение оставляет её.
- **Транзакции:** сервисы не делают `commit`, его делает вызывающий (API, планировщик). Порядок блокировок:
  orders → negotiations → order_lines.
- **Торг:** первое предложение приходит с checkout (`cart_items.offer_price_amd` или скидка на заказ). Ответ на
  каждую открытую строку: принять / отклонить / встречная. Нет ответа в срок → заказ отменён (`offer_expired`).
- **Автопилот продавца** — в процентах от цены строки (`accept_discount_bp`, `max_discount_bp` в API, `*_pct_bp` в
  `offer_rules`); старые правила с абсолютными ценами читаются как скидка от каталожной и при сохранении переводятся
  в проценты. `share_hint` показывает покупателю скидку автопринятия, порог отказа — никогда. Превью автопилота
  на фронте — `web/src/lib/haggle.ts`, держать одинаковым с `domain/negotiation.decide`. Продавец в заказе видит
  карточку клиента (`order.client`, `services/clients.py`), покупатель — нет.
- **Ошибки** сервисов — `platform/errors.py` → `{"code", "message", "details": {"problems": [...]}}`; тексты
  для кодов — `PROBLEMS` в `web/src/i18n.ts`.
- **Документы заказа** выпускаются сами: счёт и накладная при подтверждении, акт при приёмке; `payload` —
  замороженный снимок. Официальные e-документы КГД — только номера, вводит продавец.
- **Новые enum-значения** в существующей колонке: автогенерация не меняет CHECK — пересоздайте ограничение вручную
  через `op.f('ck_<table>_<enum>')` (пример — миграция `0003`).
- **Доступ** (docs/05): каталог публичный, гость не видит продавца. Компания может быть и покупателем, и продавцом
  (`is_buyer`, `is_seller`); сторона запроса — режим `X-Mode`. Покупать — после загрузки выписки из госреестра,
  продавать (принимать заказы) — после проверки оператором. Права — `platform/authz.py`, `Actor.require()`.
- **Уведомления:** событие заказа в `outbox` → `services/notifications.fan_out` создаёт строку на каждого участника
  другой стороны: канал `app` (колокольчик) сразу, копии `email` / `telegram` отправляет `deliver_pending` в планировщике
  (повтор до 5 раз, `dedupe_key` не даёт задвоить). Тексты — `TEXT` на сервере и `NOTICES` в `web/src/i18n.ts`, держать
  одинаковыми. Новый тип события — добавить в `KINDS`. Адреса `@qb.local` писем не получают.
- **Чат по заказу** — `order_messages`, событие `order.message`; чтение чата гасит его уведомления.
- **Telegram:** привязка через `t.me/<бот>?start=<токен>` (подписанный, 15 минут), бот в профиле compose `bot`.
- **Импорт прайса** (`/seller/import`): `core/spreadsheet.read_table` читает .xlsx (openpyxl) или .csv (`;`/`,`, UTF-8
  или cp1251), `domain/price_import` угадывает колонки (заголовки hy/ru/en и ArmSoft) и строит план, сервис
  применяет его без хранения файла — клиент присылает строки дважды (предпросмотр и применение). Сопоставление — по
  артикулу (код ArmSoft), без артикула или у товара без артикула — по точному названию; повторная загрузка того же
  файла ничего не меняет. Строки с ошибками пропускаются.
- **Поиск по ИНН** (`REGISTRY_PROVIDER=eregister`): API у госреестра нет, `integrations/eregister.py` читает его
  открытые страницы (поиск → карточка на hy и en), кэш в Redis на сутки (не найдено — 3 ч, ошибки не кэшируются).
  Незнакомая вёрстка или сбой — `RegistryUnavailable`, анкета открывается для ручного ввода. Директора и налогового
  режима в открытой карточке нет. Тесты — на сохранённых страницах `tests/fixtures/eregister`; если реестр поменяет
  вёрстку, пересохраните их и поправьте разбор.
- **Контакты** (`domain/contacts.py` = `web/src/lib/contacts.ts`, держать одинаковыми): телефон РА → `+374 XX XXX XXX`,
  почта (формат + подсказка опечатки в домене), счёт — 16 цифр. Проверяются при регистрации и правке реквизитов.
- **Адреса доставки** — в кабинете компании, не при регистрации: несколько на компанию, у каждого принимающий
  (`contact_name`, `contact_phone`) и заметка для водителя; удаление = архив (`archived_at`), старые заказы и накладные
  ссылаются на адрес. Принимающий печатается в накладной.
- **Подсказки адреса**: улицы Еревана на hy/ru/en с районами лежат в `web/src/data/yerevan-streets.json`
  (`scripts/build_yerevan_streets.py`, OpenStreetMap, ODbL — подпись в списке подсказок). Готовый адрес с домом
  проверяет `GET /geo/resolve` через Nominatim: не чаще 1 запроса в секунду на всё приложение, кэш сырых ответов на
  30 дней; подсказки по мере ввода через Nominatim запрещены его правилами.
- **Кросс-сейл в корзине** (`GET /cart/suggestions`, правила — `domain/suggestions.py`): добрать до минимума или
  бесплатной доставки у того же продавца, следующий оптовый порог, услуги продавца, «вы обычно берёте» (90 дней),
  сопутствующие категории у других продавцов, возящих в район адреса. Товар — один раз, под самой полезной причиной.
  **Услуги** — товар с `is_service`: в каталоге не показываются, без торга, предлагаются в корзине.
- **Карточка товара** (`/product/:id`, `GET /products/{id}`): фото, цены и пороги, условия заказа, описание,
  характеристики, сертификаты. Характеристики — `products.specs` (JSON), набор зависит от категории и задаётся только
  в `domain/product_specs.py` (маркировка ТР ТС 022/2011, термическое состояние мяса по ТР ТС 034/2013); формы и
  карточка строятся из `GET /product-specs`, лишнее для категории отбрасывается при сохранении, у услуг характеристик
  нет. **Фото** (до 6, первое — главное) пересжимаются Pillow в WebP 1600 px + превью 480 px `-s.webp` без EXIF и
  отдаются публично `/media/products/...` с годовым кэшем; фото из `hidden_images` продавец видит, покупатели — нет
  (главное фото всегда показано). **Сертификаты** (`product_documents`: вид, номер, срок) —
  файлы закрыты, открываются только после входа; гость видит, что документ есть, но не файл и не продавца.
- Поиск: `products.search_text` собирается `core/search.build_search_text` из всех языков + транслитерации;
  обновляйте его при каждом изменении названия.

## Дизайн-система (web/src/styles.css)

Принцип — **«мягкое стекло: серый, жёлтый, чёрный»** (с 27.10.2026, по референсу Liquid Glass). Спокойный серо-шалфейный
фон с мягким светом (`body::before`), контент — на молочных полупрозрачных карточках, плавающее управление —
настоящее стекло с размытием. Чёрный — вес и действие, жёлтый `--accent` — единственный живой цвет: «ваше»,
следующий шаг, сегодня, выгода. Красный `--danger` — только ошибки и отказ.
- **Стекло — для управления, не для контента:** `backdrop-filter` только у плавающих элементов (`.tabbar`, `.topbar`,
  `.sheet`, `.address-options`, `.search`, боковая панель). Карточки контента — `--surface` без размытия (фон под ними
  спокойный, на слабых телефонах не тормозит). Стекло на стекло не кладём. `prefers-reduced-transparency` и
  браузеры без blur получают сплошные поверхности.
- **Подпись:** чёрная капсула в жёлтой карточке — полоса корзины (`.cartbar`: сумма в капсуле), плитка следующего
  шага (`.next` + `.clock`), срочный заказ. Капсула — `--capsule`, чёрная в обеих темах; активная вкладка — жёлтый
  кружок, счётчики — чёрные.
- **Шрифт:** Manrope + Noto Sans Armenian. Крупные числа и заголовки — лёгкие (400) и большие, подписи разделов —
  мелкие, жирные, капсом с разрядкой (`.section-title`, `.eyebrow`).
- **Форма:** всё круглое и мягкое: `--r` 30px, кнопки и чипы — «пилюли», круглые иконки `.ibtn`; тень мягкая,
  у стекла светлый верхний блик `--glass-edge`. Токен `--card` — цвет, противоположный `--ink` (текст на чёрном),
  фон поверхностей — `--surface`.
- **Данные:** заполненное — чёрным, неизвестное — штриховкой `--hatch`.
- **Ключевые компоненты:** `OrderMeter`, `PriceDial`, `ConvergenceTrack`, `StageRail`, плитка `.next` с `Countdown`,
  полоса корзины `.cartbar`, чёрная плитка итога в корзине, KPI-плитки на доске продавца.
- **API для экранов:** заказ отдаёт `next_step`, `deadline`, `saving_amd`, `events`; список — то же + `preview`.
- **Движение:** короткое для частого (`--t-fast`), пружина `--spring` для появления, лёгкое сжатие при нажатии;
  `prefers-reduced-motion` отключает анимации. Тёмная тема — те же токены (графитовый фон, тёмное стекло).
